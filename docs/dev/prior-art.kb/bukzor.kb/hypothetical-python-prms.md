# hypothetical-python-prms — the counterfactual probe

A thought experiment, not a built system (design discourse,
2026-07-28): a Python system over llm-kb data, implementing as much of
`../../design.ledger.kb/` as it can, traced to a Pareto frontier. The
one quarry entry never lived-in; it earns its file because the
counterfactual audited the ledger's own layering and relocated a wall.

**The frontier:** P0 — grep + agent, today's artifact. P1 — a
~500-line projection tool: hashing, standing, staleness, derived
sigils, well-formedness CI; roughly 90% of the `ledger` theory, every
claim capped at stated depth. P2a — an embedded Metamath kernel
(mmverify.py is ~350 lines): full depth ladder per claim, laws still
scripts. P2b — a homegrown MLTT kernel: the full spine in principle —
registry as object-language value, laws as kernel-checked theorems —
at the price of maintaining a proof language solo, forever. P3 —
Python shrinks into the one seat the design reserves for untrusted
code (`UNTRUSTED_XLATE`), and "a Python PRMS" and the committed design
become the same object.

**Gems:**

- The partition audit: nearly all of `ledger` is implementable as data
  plus projections — the theory really is substrate-free, as its
  placement claims — and the claims that fail are exactly the `host`
  spine. The layering holds under counterfactual load.
- The wall is in `world`, not `host`. Proof kernels exist in Python
  (mmverify.py, HolPy, tutorial-grade lambda-Pi checkers), and `host`
  names engine parts, never an engine — so `NATIVE!` is reachable in
  Python in principle. What Python cannot supply is the rented half:
  `DAILY_LOOP`, `ECOSYSTEM`, `PLEASURE_RANK`. `DECISION!` rests on
  utility, not feasibility, and `TWO_POLES` survives the stress test:
  Python-with-kernel is the Metamath pole reopened with different
  tooling, not a third pole. Its one edge over the committed design is
  rent — no elaborator API to ride (`CHURN`) — which is the
  reopener-shaped residue `DECISION!` should watch.
- P1 is the knee of the curve, and not throwaway: its parser and
  hasher are the translator's front half at P3, and run over
  `../../design.ledger.kb/` today it would derive sigils and report
  staleness — `SIGIL_RENDER`'s "in the design they are derived" made
  true early, an `IMAGE!` fidelity raise available before any Lean
  exists. This is `../../user-stories.kb/shallow-corpus-still-pays.md`
  nearly whole: the story the Python frontier serves, and cheaply.
- `META_DEPTH` adjudicated the hypothetical before it was posed — "a
  realization that caps a law's depth below proof is defective, not
  different" is the P1/P2a verdict verbatim — which makes
  `../../user-stories.kb/legislate-against-my-failure-modes.md` the
  story that forces the engine: laws as kernel-checked theorems is the
  demand no Python point short of P2b serves. A ledger dense enough to
  contain the review of its counterfactuals is what
  `SELF_CONTAINED!` buys.

**Miss:** the organ Python cannot rent — the daily loop. Every
genuinely-Python point either caps laws below proof (`META_DEPTH`'s
defect: P1, P2a) or buys the spine by becoming a solo-maintained proof
assistant with a corpus of one user (P2b). And being hypothetical, its
findings are reasoning, not lived evidence — one evidentiary grade
below the rest of the quarry.
