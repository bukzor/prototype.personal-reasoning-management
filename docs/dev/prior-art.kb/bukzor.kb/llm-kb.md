# llm-kb — files as items, ls as index

`Skill(llm-kb)`: `.kb/` collections — one item per file, kebab-case
filenames as discovery affordances, CLAUDE.md as maintenance guide
(never enumeration), JSON-schema-validated frontmatter, synthesis files
only where they beat `ls`. The substrate every later system in this
family stands on, and PRMS's own authoring surface: the translator
ingests llm-kb frontmatter (`LEAN_REALIZE+`).

**Gems:**

- Discovery priced at a directory listing: the filename does the
  indexing, so capture is one file write — `AFFORDANCE+` and
  `NAMES_INDEX+` as lived practice before they were claims.
- Schema-validated frontmatter on prose: the machine-readable layer the
  translator needs already exists, with a working validator
  (`UNTRUSTED_XLATE`'s ingestion point).
- The maintenance-guide/enumeration split: guides say what belongs,
  `ls` says what's present — the corpus stays cheap to keep honest.

**Miss:** pure librarianship. Naming, discovery, loading, maintenance —
and no epistemics in the primitive: no warrant, no dependency
semantics, no revision propagation. The ACS audit's verdict: llm-kb and
ACS are complementary halves, and this is the half that shipped.
