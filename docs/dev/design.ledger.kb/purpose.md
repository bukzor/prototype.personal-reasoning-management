# purpose

Why the system is being built and for whom: the procurement question and its
utility function. Says what is wanted, never what supplies it.

- `prior:` ledger
- `ontology:` user, corpus, procurement, candidate, domination, utility, daily
  use, the vocabulary of using a tool — syntax, CLI, CI, latency — the
  experiment's two poles: speed-of-thought capture and constructive
  reasoning, the continuum of elaboration between them, inference over
  the corpus, and the applications built above the base
- `defeated by:` a different user, a different corpus, or a different utility
  function

- PROCURE!: Purpose is procurement — selecting one system to use daily for the user's own reasoning -- authority: user
- CORPUS!: The claim corpus is the user's own reasoning, across all realms; dependently-typed-programming-language (DTPL) metatheory and verified implementation is the first realm, the one where constructive claims pay most -- authority: user
- SPAN! <- PROCURE!, CORPUS!: The experiment is the span: one system meeting entirely-informal speed-of-thought needs and proof-relevant constructive reasoning — warrants that hand over the object they promise — all at once, joined by a useful, ergonomic, gradually-elaborated continuum. The bet, which may never pay out, is that the poles coexist in harmony; a candidate that serves either pole by sacrificing the other, or both poles without the continuum, fails the experiment -- authority: user
- DAILY_CRITERIA! <- PROCURE!: The utility function is daily pleasure of use — snappy CLI, clean syntax, easy and fast CI, general snappiness -- authority: user
- INFER! <- SPAN!, DAILY_CRITERIA!: Constructive inference over the corpus — validation is one of its types, the inference whose extracted object is a proof of well-formedness — is asserted purpose: the system is procured to infer, not only to record. It sits below everyday use: inference may never tax the informal pole or the continuum, and where they compete for design attention, everyday use wins -- authority: user
- UNDOMINATED <- PROCURE!: Candidate-set membership = undominated ∧ prima facie viable; dominated arms buy no procurement information
- GENERIC_BASE! <- CORPUS!, CLAIMS_ONLY!, META_DEPTH: The system's own ontology stops at generic knowledge and reasoning — claim, evidence, degree, defeat, identity, law — the vocabulary common to every realm and every application. Genres — decision, question, task — are application theories built above the base: each adds vocabulary as content shape and laws over it, under the same prior/confinement/conservativity discipline theories already obey, and none adds a node type. A law enters the base only when every application needs it; "every decision has a reopener" is priced above the line -- authority: user
