# ledger

What a claim is, and what follows once claims accumulate: standing, identity,
trust, and the propagation of change. The theory the system is a ledger *of*.

- `prior:` stance
- `ontology:` claim, stipulation, assertion, warrant, authority, checker,
  verdict, depth, status, hypothesis, hash, trust base, staleness, law,
  source, evidence, degree, defeat, trigger
- `defeated by:` a second node type — anything that must be represented and is
  not a claim

- CLAIMS_ONLY! <- PARSIMONY!: Claims are the sole node type; the graph is claims and references among claims, nothing else -- certified(review 089)
- STIP <- REGRESS_ACT!, AUTHOR_ACTS: The simplest claim is a stipulation: fiat = the authored decision to assume; authority attaches to the assumption act
- ASSERT!: All non-stipulated claims are asserted: proven exactly to the extent their requirements are proven -- certified(review 089)
- LEAST_FIX! <- ASSERT!: Provenness is the *least* fixpoint of ASSERT. ASSERT is a recursive definition over a graph that permits cycles, and a cycle of mutually-asserting claims satisfies it both as all-proven and as all-unproven; least makes provenness an inductive predicate — cycles are unproven, the predicate stays cheap to compute, and the theory stays predicative: nothing is proven by appeal to a totality containing it -- authority: user
- WARRANT! <- STIP, CLAIMS_ONLY!: A warrant is a discharged stipulation — stipulation and warrant are one mechanism at two stages; warrants are claims, inheriting full depth/status structure -- certified(review 089)
- CHECKER <- REGRESS_ACT!, PARSIMONY!: Inference-validation lives in checkers — meta-level programs over the claim graph. Carroll's regress admits two exits: make inference a primitive *in* the ontology, or a procedure *over* it. This is the second — the LCF/de Bruijn choice, the one that won historically — so the regress terminates in trusted code, and the ontology gains no node type
- VERDICT <- STIP, CLAIMS_ONLY!, NAME_THE_JUDGE!: Checker verdicts are stipulated claims whose authority is checker+version -- certified(review 089)
- DESIGN_FIAT <- STIP, CHECKER, REGRESS_ACT!: An underdetermined choice is legitimately terminated by stipulation with an authority, exactly as CHECKER terminates the inference regress
- LAST_WINS!: Restating a claim supersedes its prior version; the claim set is the union, last wins -- authority: user
- HYP_CONTENT: A claim's hypotheses are part of its statement content, not an annotation on it
- DEPTH_ATTEST <- VERDICT, CHECKER: Depth-verdicts attest artifact existence — shallow = no verdict, described = a checker verdict on a statement object, proof = a checker verdict on a proof object
- HASH_ID: Claim identity is a content hash of the surface statement; names are mutable pointers; staleness = a dependent proven against a superseded hash
- SURFACE_SPLIT <- HASH_ID: Authoring surface and system of record are separable because identity is content — a claim hashed from any surface is the same claim, so the surface can optimize for entry cost and the record for verification, neither constraining the other
- TRIGGER_CONTENT <- HYP_CONTENT, SURFACE_SPLIT: A push trigger — "when acting on X, this claim bears" — is an applicability hypothesis, statement content like any other, never a fact of the file's path; the engine can then enumerate what watches an act, "every act-type has a claim watching it" is a stateable law, and trigger-named paths remain a legitimate surface projection of the same data
- MONOTONE <- HASH_ID, VERDICT: The verdict record is append-only and monotone, and this is derived rather than imposed: a verdict attaches to a content hash, so "checker C accepted claim #a3f" is a historical fact nothing later falsifies. A claim's *change* repoints a name to a new hash — that is staleness, not revocation — and an authority's *fall from trust* is a filter applied at query time, not a mutation of the record. Revocation is thus not forbidden but unrepresentable
- ACCEPTED <- MONOTONE: A verdict is *accepted* iff it is recorded; presence is acceptance. Nothing adjudicates between authorities, so there is no global "accepted" — a claim can be simultaneously proven-per-checker and retracted-per-user, and reporting both unreconciled is the point. Adjudicating would be the ledger evaluating a proposition
- STATUS <- VERDICT, DEPTH_ATTEST, ACCEPTED: A claim's status is the set of authorities of accepted verdicts about it. Set-valued rather than a ladder because real checkers disagree — typechecking, termination and positivity are separate checkers, and one definition can pass some and fail others — so the shallow/described/proof ladder is a special case of the checker set, not the general shape
- SOURCE! <- VERDICT, NAME_THE_JUDGE!: Verdict-issuers are sources of evidence of validity — the user, agents, checkers, imported documents — one kind, not four: a verdict is evidence from a source, a checker is a source whose evidence is mechanical, and an authority is a source pinned to a version or date. Nothing about a verdict's treatment varies by source kind -- authority: user
- DEGREE! <- SOURCE!, ACCEPTED: A verdict carries degree — independent axes of judgment: truth (correspondence), certainty (confidence in it), utility (value of it) — each defaulting to full, so an uncontested claim spends nothing stating them. Degree is the source's judgment recorded, never the ledger's; sources disagreeing in degree is ACCEPTED's unreconciled report, not a conflict to resolve -- authority: user
- PROJECTION <- STATUS, DEGREE!, MONOTONE: Whatever a reader consults about standing — status, staleness, confidence summaries — is a projection computed from the evidence set, never independently authored, because a stored projection can drift from its inputs and then it lies. STATUS is the first projection; staleness — a verdict attached to a superseded hash — is the second, already derivable since MONOTONE pins every verdict to the hash it judged
- UNFORCED! <- ACCEPTED, PROJECTION: Anything computable from the evidence set may be computed — winners under any semantics included; what can be computed will be. ACCEPTED bars the record from ruling, not readings from ruling: the entitlement it protects is deferral — representing a disagreement never compels resolving its fallout, now or ever -- authority: user
- LINK_CLAIM! <- CLAIMS_ONLY!, CHECKER: A support step is a claim exactly to the extent it is informal: "P therefore Q", while unformalized, is an ordinary claim — statable, contestable, deepenable like any other. Formalizing it discharges it into a checked derivation, which is not contestable content, only distrustable through its trust base. Inference's two poles — claim content when informal, checker procedure when formal — are joined by deepening, not by a third thing -- authority: user
- DEFEAT <- LINK_CLAIM!, DEGREE!, MONOTONE: Defeat adds no node or edge type: a rebuttal is a contrary-degree verdict on the claim, an undercut is a contrary-degree verdict on the support-step claim, and against a checked derivation the only coherent attack is distrust of an authority — already a query-time filter. Laws quantify over defeat by quantifying over verdicts. An argued rebuttal exists as an ordinary claim besides; asserting it is what issues the contrary verdict — the claim is the argument, the verdict is the residue standing sees
- TRICHOTOMY <- STATUS, ACCEPTED, PROJECTION: The prior notation's invariant — every claim sound, open, or retracted, for each party — survives as a per-source projection: restricted to one source's accepted verdicts, every claim is exactly one of the three. A global trichotomy would be the adjudication ACCEPTED refuses, and the invariant's own "for both parties" already conceded so
- REOPEN <- HYP_CONTENT, DEPTH_ATTEST, TRIGGER_CONTENT: A claim's reopening condition — a decision's, archetypally — is content on the claim itself, climbing the ordinary depth ladder: a reopener only a human can recognize is the stated rung, a machine-checkable one is described or proven and the staleness law watches it — convention versus mechanism is not a fork to decide but depth again
- META_DEPTH <- CLAIMS_ONLY!, DEPTH_ATTEST, LEAST_FIX!: A law — a claim about the claim set — is an ordinary claim and climbs the same depth ladder: stated, described, proven. Nothing in this ontology caps a law's depth, so a realization that caps it below proof is defective, not different; LEAST_FIX's inductive provenness is the first law
- TRUST_BASE <- HYP_CONTENT, VERDICT: Trust base = the claim's hypotheses ∪ the axioms admitted at the corpus boundary ∪ the authorities of its verdicts; the first component is checker-enforced
- CHECKER_COLLAPSE <- CHECKER, TRUST_BASE: The trusted code CHECKER terminates in is not a fixed floor: a checker's judgment, restated as a claim the proof-checker itself can evaluate, moves that checker out of the trust base. Checkers above the proof-checker are reducible trust debt; the floor is the one checker every proof already pays for
- STALE_PROP <- HYP_CONTENT, HASH_ID: Stipulation revision propagates staleness automatically, since hypotheses are statement content
- QUOTIENT! <- HASH_ID: The hash quotient is mechanical only — character encoding, trailing whitespace, line wrap — never lexical, never semantic: any edit a diff would show is an identity change. The quotient prices revision: a verdict strands exactly when the statement its source endorsed is no longer the statement on record -- authority: user
- ID_BOUNDARY! <- HASH_ID, HYP_CONTENT, DEPTH_ATTEST: Identity hashes the statement alone, hypotheses included, and the boundary is uniform across planes: what changes where the claim bears is propositional and inside the hash; what changes only why it is believed — premises, proof objects, verdicts, degree — is motivation or evidence, outside it. A proof is validity support; it deepens the claim and never migrates it -- authority: user
- EQUIV_CLAIM! <- CLAIMS_ONLY!, HASH_ID, QUOTIENT!: Sameness of statement beyond the mechanical quotient is itself a claim — stated, contested, verdicted like any other, with a designated canonical member — never a hash rule. Scoped laws of normalization or confluence may later consume such claims; the hash stays dumb precisely so that equivalence stays defeasible -- authority: user
- NAME_BLIND <- HASH_ID, QUOTIENT!: No law reads names: label continuity is authorial convenience, not machine evidence — "same label, therefore same question" would be semantic normalization smuggled back in through naming -- authority: user
